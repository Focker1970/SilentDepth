SilentDepth Role Specification

SilentDepth 役職仕様

SilentDepth を「第二次世界大戦の北大西洋における Uボートのコンボイ戦シミュレーション」として実装するための役職設計資料。 急速潜航、潜航後戦闘、指揮系統、UIマッピングまでを実装向けに整理している。

対象: Uボート / 北大西洋 / コンボイ戦 / 急速潜航 / 潜航後戦闘

概要

目的は次の3点。

  1. 急速潜航 と 潜航後戦闘 を明確に分離する
  2. 艦長 / ソナー員 / 雷撃士 / 航海長 をプレイヤーが切り替えて遊べる主役職にする
  3. 機関部・見張り・通信士などの非プレイ部署も、戦闘結果に影響するシステム役として組み込む

部署別コマンド設計案

1. 艦長・発令所

  • 航行指示: 微速 / 半速 / 全速 前進 / 後進 面舵 / 取舵
  • 深度指示: 浮上 潜望鏡深度 シュノーケル深度 指定深度 急速潜航（Alarm）
  • 戦闘指示: 戦闘配置 静粛潜航 デコイ射出
  • 観測: 潜望鏡昇降 倍率変更 ターゲットロック

2. 第1当直将校（TDC）

  • 観測データ入力: 距離 速度 AOB
  • 魚雷設定: 深度設定 信管設定 速度設定
  • 発射シーケンス: 同期 発射

3. 機関長（LI）

  • バラスト・トリム制御: 注水 排水 艦首艦尾バランス調整
  • 動力切り替え: ディーゼル / モーター切替 充電モード移行
  • ダメージコントロール: ビルジポンプ 修理優先度設定

4. 音響・通信部門

  • ソナー操作: 聴音角ダイヤル 周波数フィルター
  • 報告要求: 接敵報告 距離・速度推定
  • 通信: 暗号電文送受信 群狼作戦要請

5. 水雷部門

  • 発射管管理: 注水 前扉開閉 引き出し整備
  • 発射準備: ジャイロ同期 発射管準備完了報告

急速潜航フェーズ仕様

フェーズ概要

  • トリガー: Alarm! ボタン、または敵航空機 / 駆逐艦の近距離発見
  • 制限時間: 30秒
  • 勝利条件: 制限時間内に 潜航完了 状態へ移行
  • 失敗条件: ハッチ未閉鎖、吸排気弁未閉鎖、潜航遅延、敵発見状態で浮上継続

潜航後戦闘フェーズ仕様

艦長

  • 主目的: 戦術判断の最終責任者
  • 主要操作: 観測モード切替、雷撃許可、静粛航行、回避命令、離脱命令
  • 主要入力: ソナー報告、雷撃解、航海情報
  • 主要出力: 艦長命令 と 優先度
  • UI要素: Command Chain, Captain Intent, 潜望鏡, 浮上双眼鏡, Alarm!

ソナー員

  • 主目的: 外界情報の中核
  • 主要操作: 受動聴音、能動ソナー、接触分類、報告
  • 主要入力: 音響信号、接触履歴
  • 主要出力: 方位、推定距離、種別、速度評価、護衛接近警報
  • UI要素: ヘッドホン向け音響、接触一覧、艦長向け報告欄

雷撃士

  • 主目的: 命中可能な射撃解を作る
  • 主要操作: 目標選定、進角計算、発射管準備、発射
  • 主要入力: 艦長観測値、ソナー方位、敵針路・速力
  • 主要出力: 進角, AOB, 会敵時間, 発射可否, 注水状態
  • UI要素: 雷撃盤、最良射撃解、報告欄

航海長

  • 主目的: 深度・針路・艦姿勢の維持
  • 主要操作: 深度変更、針路変更、速力変更、潜望鏡深度維持
  • 主要入力: 艦長命令、敵方位、潜航状態
  • 主要出力: 針路維持、回避コース、離脱コース
  • UI要素: Helm Orders, Nav Plot, 報告欄

ゲームの方向性案

スタイルA: フルボイス・コマンド没入型

  • プレイヤーは艦長として音声または疑似音声UIで命令を下す
  • NPCクルーが復唱し、命令遅延や誤認がそのままゲーム性になる
  • 没入感は非常に高い
  • ただし実装難度とUI依存が高く、初期開発向きではない

スタイルB: 自律型AIクルーとパイプライン管理型

  • プレイヤーは命令とSOPを定義し、クルーが半自律で動く
  • 非常時だけプレイヤーがオーバーライドする
  • 役職間連携をシステムとして表現しやすい
  • 長期的には非常に良いが、まずは基礎ロジックの整備が必要

スタイルC: データ駆動・ハードコア演算型

  • ソナー、TDC、雷撃諸元をプレイヤー自身が詰める
  • 命中時の達成感が大きい
  • ただし入口が硬すぎるとプレイヤーを選ぶ

推奨方針

スタイルB を土台にしつつ、雷撃だけスタイルCへ寄せる 方向が最も合う。

  • Uボートらしさの核は各部署の連携にある
  • 現在の Command Chain と役職タブ設計と相性が良い
  • 雷撃だけハードコア寄りにすると役職差が立つ
  • スタイルAは魅力的だが、後付けの拡張要素として扱うのが安全

具体的なゲームデザイン提案

  • 基本ループは 艦長が命令 -> 各部署が半自律で実行 -> 必要時に役職切替して介入
  • 緊急時だけ 急速潜航フェーズ のような手動密度の高い局面を作る
  • 雷撃席では 距離 / AOB / 進角 / 信管 / 注水 / 同期 を段階化し、ハードコア寄りにする
  • ソナー席はヘッドホン前提の主役席として強化する
  • 戦略層として後から 通信 群狼作戦 補給 損傷修理 を積み増す

ドイツ語復唱テンプレート仕様

基本方針

  • 艦内の命令復唱は、まず テンプレート固定文 で実装する
  • 重要操作は 艦長命令 -> 復唱 -> 実行報告 の3段構成にする
  • ドイツ語は雰囲気重視だが、短く、聞き取りやすく、役割が分かる定型文を優先する
  • LLMは初期段階では使わず、まずは安定したテンプレートテーブルで運用する

役職ごとの復唱ルール

艦長

  • 艦長自身は基本的に 命令発話のみ
  • 命令は短く、他部署の復唱を誘発するトリガーとして機能する
  • 長文説明は音声ではなくUIログに出す

ソナー員

  • 接触探知時は 方位 -> 種別 -> 推定距離 の順で報告する
  • 同一接触を短時間に何度も繰り返さない
  • 駆逐艦 高速接近 接触喪失 は高優先度

雷撃士

  • 用意 同期 発射 命中音確認待ち の段階で報告する
  • 発射前の報告にはできるだけ Rohr番号 を含める
  • 雷撃解が成立していない時は、不成立理由を簡潔に示す

航海長

  • 深度・針路・トリム状態の報告を担当する
  • 急速潜航中は報告頻度を高める
  • 定常時は変化があった時だけ短く報告する

機関部

  • 急速潜航と損傷時のみ前面に出す
  • 停止完了 切替完了 閉鎖完了 など結果報告を明確にする

発話頻度制御

  • 同じ話者が短時間に連続で喋りすぎないように cooldown を設ける
  • critical イベントのみクールダウン無視
  • 1イベントにつき 1命令 + 1復唱 + 1完了報告 を基本単位とする

TTS実装方針

採用方針

  • 初期実装は ブラウザ標準TTS を使う
  • Web Speech API の speechSynthesis を第一候補にする
  • 音声生成はローカルブラウザ依存とし、サーバー側音声合成は後続対応にする
