SilentDepth 開発タスク一覧

本書は GAME_SPEC.md と ROLE_SPEC.md を、そのまま実装タスクへ分解し、開発順にチェックできる形へ落とし込んだものです。

遊べるコア戦闘ループを先に作る 雰囲気演出はコア成立後に積み増す P1 - P2 - P3 の順に開発する

マイルストーン

  • ☑ M0: 役職UIと指揮系統UIが仕様に沿って安定表示される
  • M1: 平常時 -> 接敵 -> 潜航戦闘 -> 雷撃 -> 離脱 が1ミッションとして成立する
  • M2: Alarm! による急速潜航フェーズが成立する
  • M3: ドイツ語復唱とTTSで艦内演出が成立する
  • M4: 損傷、静粛潜航、爆雷回避で生残戦が成立する
  • M5: AIクルーとAI駆逐艦艦長でリプレイ性が成立する
  • M6: 戦略層を含むキャンペーン構造が成立する

優先度定義

  • P1: 最優先。ゲームの核
  • P2: 体験を深くする中核
  • P3: 拡張とリプレイ性

Phase 0: 既存プロト整理

目的: 現在の画面プロトを、役職仕様と指揮系統仕様に揃える

P1 タスク

  • ☑ battlePhase の暫定状態管理を追加する
  • ☑ 役職タブ構成を主役職前提で整理する
  • ☑ Command Chain を固定構造に統一する
  • ☑ 各役職パネルに現在任務、主要操作、最新報告を表示する
  • ☑ Bridge Log の文面形式を統一する
  • ☑ viewMode と captain intent の表示更新を一貫させる

P2 タスク

  • ☑ 艦長席の視界オーバーレイを微調整する
  • ☑ 各役職パネルの情報密度に差をつける
  • ☑ 状態表示の語彙を整理する

確認項目

  • ☑ 主役職4つへ切り替えた時に役割が一目で分かる
  • ☑ 艦長命令の後に各部署の反応が追える

Phase 1: コア戦闘ループ

目的: 索敵 -> 接敵 -> 潜航戦闘 -> 雷撃 -> 離脱 を最低限遊べる形にする

P1 タスク

  • ☑ battlePhase を patrol / contact / submerged_combat / attack / egress で実装する
  • フェーズごとの遷移条件を明示する
  • ☑ 平常時の接触発見イベントを実装する
  • ☑ 視認とソナーの両方で敵発見できるようにする
  • ☑ 敵優位と自艦優位の分岐を入れる
  • ☑ 潜航戦闘中の基本ループを作る
  • ソナー報告から接敵情報が更新されるようにする
  • ☑ 航海長操作を戦術結果へ反映させる
  • ☑ 雷撃シーケンスを段階化する
  • 離脱フェーズへの遷移条件を実装する
  • 最低限の戦果判定を実装する

P2 タスク

  • ミッション開始条件を複数パラメータで持たせる
  • 接敵ごとに敵編成を変えられるようにする
  • フェーズ別のHUD文言を用意する

確認項目

  • プレイヤーが詰まるフェーズがない
  • 雷撃後に離脱判断まで要求される

Phase 2: 急速潜航フェーズ

目的: Alarm! 発令から完全潜航までの30秒をゲームとして成立させる

P1 タスク

  • battlePhase に alarm_dive を追加する
  • Alarm! トリガーを実装する
  • 急速潜航専用UIを追加する
  • 30秒タイマーを追加する
  • 部署別タスク進行を状態として管理する
  • 急速潜航の主要アクションを個別タスク化する
  • 成否で被探知率、初期深度、損傷を補正する
  • 成功時と失敗時の分岐を作る

P2 タスク

  • 前部移動を演出と数値効果の両方で表現する
  • 航海長操作が潜航時間へ効くようにする
  • 機関部の遅延や故障イベントの余地を作る

確認項目

  • Alarm! は通常の深度変更より明確に別物として感じられる
  • 成否の違いがその後のプレイに残る

Phase 3: 音声復唱・艦内演出

目的: 艦内の命令と復唱を、見えるだけでなく聞こえるものにする

P1 タスク

  • ドイツ語復唱テンプレートテーブルをデータ化する
  • 復唱イベント構造を定義する
  • 命令イベントから復唱イベントを発火させる
  • UIログに原文と日本語意味を表示する
  • 音声ON/OFF設定を追加する
  • テキストのみでも成立するフォールバックを用意する

P2 / P3 タスク

  • speechSynthesis ベースのTTS再生を追加する
  • 優先度キューと同一話者クールダウンを実装する
  • ベル、爆雷、機関音と音声のミックス方針を実装する
  • 話者別の話速や声質の設定項目を持たせる
  • ブラウザごとの de-DE 音声差分を吸収する
  • 音声入力による艦長命令の受け口を検討する

確認項目

  • 重要命令は必ず復唱される
  • 音声を切ってもテキストだけで進行に困らない

Phase 4: 損傷・静粛潜航・回避

目的: 雷撃後の生残戦を、独立した緊張フェーズとして成立させる

P1 タスク

  • 損傷部位モデルを追加する
  • 系統損傷を分ける
  • silent_running フェーズを実装する
  • 騒音値が敵探知率に影響するようにする
  • 爆雷攻撃イベントを実装する
  • 回避行動の結果が被害量を左右するようにする
  • 応急修理の優先度を持たせる

P2 タスク

  • 艦内ノイズ要素をイベント化する
  • 深深度と圧壊リスクを導入する
  • 損傷が役職UIに与える制限を設計する

確認項目

  • 雷撃後に生還のための判断が必要になる
  • 静粛潜航が体感として分かる

Phase 5: AIクルー / AI駆逐艦艦長

目的: 役職間連携と敵護衛の判断に変化を持たせ、毎回違う戦闘にする

P1 タスク

  • 敵駆逐艦艦長AIの意思決定レイヤーを作る
  • 捜索、護衛優先、追尾、爆雷投下、再捜索を状態化する
  • クルーSOPベースの半自律行動を作る
  • 各部署が一定範囲まで自動実行するようにする

P2 / P3 タスク

  • 敵艦長に 慎重 aggressive 執拗 などの性格パラメータを持たせる
  • 副長、機関長、ソナー員から短い提案を返す仕組みを追加する
  • AI提案とプレイヤー介入の優先関係を整理する
  • 生成AIは雰囲気テキストや提案補助に限定する
  • 基幹判定はルールベースで固定する

確認項目

  • AIが勝手にゲームを解きすぎない
  • 毎回同じ手順にはならない

Phase 6: 戦略層拡張

目的: 単発遭遇戦から、Uボート哨戒任務全体へ広げる

P2 タスク

  • 戦果管理をミッション外へ持ち出す
  • 補給、燃料、魚雷残数、修理状態を管理する
  • 帰投や再出撃の流れを作る

P3 タスク

  • 通信士による会敵報告や司令部応答を実装する
  • 群狼作戦イベントを実装する
  • 複数ミッションをまたぐキャンペーン進行を設計する

確認項目

  • 1回の戦闘の結果が次回以降へ意味を持つ
  • 単発プレイでも長期プレイでも成立する
